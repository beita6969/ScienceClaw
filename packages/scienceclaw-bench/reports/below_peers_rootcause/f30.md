## 1. ROOT CAUSE
**Verdict: no bug. It is capability (toolkit has no pretrained deep model and a weak instance stage) plus a small protocol effect. Agent effect ~0.**
Gap: frozen run mean 38.7 (31.6-45.3) [S:g1] vs top-3 81.1-82.6 (Swin-L/BEiT-L Mask2Former, 1407-1792 imgs at 1024) [S:arXiv 2501.00527]; HAPT 65.3 [S:2306.04557].

Decomposition of the ~43-point gap (estimate from the table, +-4):
- **(c1) instance / post-processing stage: 19 (id) to 27 (ood), mean ~23 pts.** Even with perfect semantics PQ+ is 55-63, PQ_leaf only 10-29 (best params 33), PQ_crop 26-56. Leaves have no boundary inside a binary vegetation mask, so smooth+threshold+watershed cannot split them: structural limit. Peers use learned Mask2Former queries.
- **(c2) semantic stage (35 hand features + LightGBM): 18 (id) to 24 (ood), mean ~21 pts.** id: IoU_crop 75 vs oracle 94, IoU_weed 25 vs 68. ood: IoU_weed ~1 vs 84; confusion [M]: 80% of GT-weed pixels (26.4k of 32.9k) are called crop, only 94 called weed; 8% of soil is called crop. id weed: recall 49%, precision 35%. Post-processing barely changes this (argmax vs pipeline within 1 pt).
- (b) missing pretrained backbone: this is what (c1)+(c2) are, in practice. torch is in `_PACKAGE_CANDIDATES` but not installed, so the agent cannot even try a deep model. Not separately measurable locally (no weights, no torch) [E: ~40 of 43 pts].
- (a) protocol: labelled-image count is NOT the bottleneck of this toolkit. Learning curve [M, id / ood PQ+]: n=2 38.4/28.8; 4 37.5/28.0; 8 36.7/28.2; 16 37.8/28.1; 24 41.1/27.9; 32 40.5/28.4; 64 41.4/29.8. Components: PQ_crop 32-35 (id), PQ_leaf 6-8 (id), 3-4 (ood) flat for all n; only weed IoU rises (id 6-15 -> 25; ood 1 -> 6 only at n=64), noisy. n=2 -> 64 buys ~+3 id, +1 ood. Src episodes see only 8-13 labels (one free capture): costs ~1-4 pts vs 24 [M, single-capture 37.6-40.6 id]. Held-out vs in-sample: 41 vs 46 (mine), 53 in the agent's own tuning nodes vs 41-46 held-out [S:trajectories] = ~5-8 pt overfit. 512 px: scale-2 scoring is optimistic by +0.4..+1.0 PQ+ (PQ_crop +1.3..3.5) [S:g1], i.e. protocol slightly flatters us. Data quantity vs model class: hand-feature GBM saturates at ~8 imgs; a frozen-DINOv2 head is the class that can use 24 labels (see 4). Full resolution: not measured (would 4x cost); expected small for semantics, larger for leaves [E].
- (d) agent: not a failure mode. Every final_a0 / frozen trajectory calls `ps.fit_predict(train, sem, [eval], seed=0)` and submits defaults or near-defaults; tuning nodes never beat defaults on dev (dev PQ+ 44.56 identical across episodes); one node wasted on a port-wiring error; 110-152k of 200k tokens, 469-2643 s of 3600 s; only the old probe_pass10_n3 src e02 hit token_budget (25.1). My replication with the same 24 labels gives id 45.4 / ood 30.9 (mean 38.2) = the frozen mean 38.7, so the agent adds ~0 +-3 over the default tool call.
- (e) bugs / unfair scoring: none found. Numpy PQ+ port matches the official scorer <= 0.01 at 1024 [S:g1]; pool/leak checks in the adapter pass; the only bias is scale-2 optimism above (in our favour).
Not yet ablated: 8-param grid was tuned on the same 8 imgs; a proper split would lower the 66-69 ceilings by an unknown few pts.

## 3. INTEGRATION DESIGN (scilib/phenoseg.py additions)
- `deep_probs(images, train_images, train_semantics, backbone="dinov2_l", seed=0) -> probs[N,H,W,3]`: frozen DINOv2 patch features (bilinear-upsampled) concatenated with the existing 35 hand features, LightGBM head trained on the labelled pixels; returns the same port type as `predict_probs`, so `panoptic_from_probs` and all params stay usable. `sam_instances(images, probs, ...) -> panoptic dict`: SAM2 point/box prompts from prob peaks for plants, leaves; falls back to watershed if no GPU.
- Weights: `SCIENCECLAW_MODELS` env var, default `/leonardo_scratch/large/userexternal/rqian000/models` (subdirs `dinov2/`, `sam2/`, `phenobench/`); code/venv in `/leonardo_scratch/fast/AIFAC_F02_774/rqian000`; never home. Load with `local_files_only=True`; clear error if missing (nodes have no internet).
- Code-node interpreter needs torch + torchvision + transformers + safetensors (+ `sam2` package); today none installed locally. Reuse the cu129 venv already used for vLLM on Leonardo [S:memory]. Workers must see CUDA_VISIBLE_DEVICES.
- Runtime [E]: A100: DINOv2-L @518 px ~0.03-0.1 s/img, 40 imgs + model load (1.2 GB from Lustre) < 30 s; SAM2 AMG/prompted ~1-3 s/img: 16 targets < 2 min; both far below `max_node_s=900` (`for30_phenobench.py:764`, `max_wall_s=3600`). VRAM < 8 GB, RAM < 8 GB. CPU: DINOv2-B ~2-4 s/img (40 imgs ~2-3 min OK), ViT-L 6-10 s/img (borderline), SAM2 on CPU ~1-2 min/img: infeasible. Cache features in the node dir so repeated tuning nodes do not recompute. Full-res 1024 input costs ~4x, still fine on A100.
- Objective text (DESIGN F5): only the scilib.describe entry changes, factual: "deep_probs: per-pixel class probabilities from frozen DINOv2-L features + hand features, needs GPU, ~X s per 40 images; sam_instances: ...". Do not mention the ExG-Otsu reference, the +2.0 margin, or expected scores.
- Agent role kept: it fits the head on the 24 labels, picks backbone size / feature mix / head hyper-parameters, tunes veg_thr / smoothing / instance splitter on the dev capture, chooses ensembling with the hand-feature model. Budget spend is now real decisions, not `fit_predict` + defaults.
