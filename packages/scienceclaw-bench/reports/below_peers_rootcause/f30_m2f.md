- 同行(PhenoBench 作者 PRBonn)公开了在官方 train(1,407 张)上训练的两个 Mask2Former R50 检查点(植物全景 / 叶片实例)。我下载(sha256 plants `8c24e0a228a964a7a0c4a14a616ec5843b8f5f8e9d47d7f2dd3d6b96416939d1`, leaves `70bb98c2b5db7e90fcaf90a77f969692263378b8ce9c72e7cd8579efc4352814`)、转成 HF 格式、封装为 `scilib.phenoseg_m2f.predict_panoptic`(零训练)。
- **干净的 id 池(官方 val, 64 张, 评一次, 512 px)**: 池化 PQ+ **64.96** [实测](4 个 episode: 62.01 / 68.23 / 62.82 / 66.85; 参考 20.9-29.2)。此前 agent 均值 38.7, SAM2 方案 56.45。同行: 冠军 81-83(满分辨率, 1.4k 张训练), HAPT 65.3。

## 转换与核对 [实测]
- `convert_phenobench_m2f.py` + `m2f_conv_lib.py`(HF 转换脚本的去 detectron2 版本, 加了 ResNet-50 骨干映射)。HF 键全部填满(缺失 0)。
- 坑: PRBonn 配置里 `PIXEL_MEAN/STD` 被注释, detectron2 默认生效: RGB 各通道减 `103.53/116.28/123.675`, 不除标准差, 不 /255。用 HF 默认 ImageNet 归一化时模型把所有 query 判成 no-object。改正后与官方 val 预测逐像素一致(语义 99.8-99.96%, 3 张图)。
- 官方 val 预测(`mask2former-val.zip`)在 `$L/models/phenobench_m2f/val_pred_*.zip`。

## 耗时与显存 [实测]
16 张 512 px 的 episode 约 8-13 s(含打分), 两模型约 20 GB 显存(batch 4)。同一张 64 GB A100 上同时放 3 个 SAM/本工具会 OOM, broker 已改为每卡 2 个槽位。

## Agent 路由复测（2026-10-02）

仅把 `phenoseg_m2f` 写进模块说明并不足以保证 Agent 采用它：一次 tool-ON 复测中 Agent 先调用了 Mask2Former，但看到 SAM 的可见 dev 分数后改用 SAM，held-out PQ+ 只有 id 53.5998、OOD 47.6494。为使比较发生在同一官方指标上，FoR30 episode 现在在 GPU/remote worker 可用时额外暴露两个可信工具：

- `predict_pretrained`：一键运行固定的 PRBonn plants+leaves Mask2Former，仅读取 RGB 评测图像，输出可直接提交的三数组；不拟合、不读取评测标签。
- `score_pretrained_dev`：在 trusted adapter 内运行同一模型并只返回 visible dev 的官方聚合指标，dev 标注不出 adapter，结果不参与 held-out 验收。

补充工具后用同一 Qwen3.8 tool-ON 配置各跑 1 个 episode（Leonardo `toolon_PRED3_id` / `toolon_PRED3_ood`）：id PQ+ **62.0138**、OOD PQ+ **76.8745**，均 `z=1`。这两个 e00 是对已有 R2/PRED2 e00 的**工程复测**，不是新的冻结 leaderboard 样本，不能用来挑选性改写“一次评测”汇总。轨迹显示 Agent 看到 Mask2Former dev PQ+ **75.39**，高于 LightGBM/SAM 的约 44.56/54.89，于是保留预训练输出。该结果只证明路由稳定性和工具能力，不能把预训练模型贡献写成 Agent 从零学习的增益；模型训练数据与 PhenoBench 官方 train 的重叠风险仍按上文披露。
