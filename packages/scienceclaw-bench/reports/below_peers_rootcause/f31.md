# f31 — FoR31 (ProteinGym v1.3 监督 DMS, mean per-assay Spearman ↑): 工具增强(tool-ON)后的结果

标注: [实测] = 本机/服务器实际跑出(脚本与结果在 `scripts/f31/`), [估计] = 判断, 未测。
口径: 只评"开工具"版本。id/ood 池每个方法各只评一次, 没有据此再调参(选型只用 52 个 src 试验、dev 表)。

## 0. 结论
- 工具: 新增 `scilib.proteinplm` —— ESM-2 650M(Lin et al., Science 2023)的位点对数概率与 6 个特征列(`esm_llr_masked`、`esm_llr_wt`、`esm_logp_mut_masked`、`esm_logp_wt_masked`、`esm_entropy_masked`、`esm_site_mean_llr`); `scilib.proteinfit.fit_predict_assays` 新增 `plm=True`(把这 6 列作为额外特征并入原有 ridge/LightGBM/extra-trees 秩集成)。沙箱没有 torch, 走文件中转桥到 Node0015 的 GPU 2(白名单 `proteinplm.site_logprobs`)。
- **工具本身的增益**(同一批试验、同一套 `proteinfit` 集成, 只差是否加 ESM 特征)[实测]:

| 池 | n 个 assay | 旧 `proteinfit` | + ESM-2 特征 | 配对差 (95% bootstrap) | 更好的 assay 比例 |
|---|---|---|---|---|---|
| src dev(选型) | 52 | 0.6352 | **0.6633** | +0.0281 (+0.0201, +0.0376) | 85% |
| id | 64 | 0.6616 | **0.6827** | +0.0212 (+0.0148, +0.0281) | 83% |
| ood(Tsuboyama 稳定性, 蛋白不相交) | 64 | 0.8771 | **0.8947** | +0.0176 (+0.0144, +0.0212) | 97% |

- 对同行(ProteinGym 官方 random-fold 5 折 Spearman 表, 同一批 assay 的对应列; 同行用 80% 标签, 我们每个 assay 只有 ≤1024 个训练变体、≤32 个 dev, 协议不同, 不能直接判胜负)[实测]:

| 池 | 旧 | 新 | Kermut | ProteinNPT | 新 − Kermut (95%) | 新 − ProteinNPT (95%) |
|---|---|---|---|---|---|---|
| id | 0.6616 | 0.6827 | 0.7041 | 0.6990 | −0.0213 (−0.0413, −0.0010) | −0.0163 (−0.0321, −0.0017) |
| ood | 0.8771 | 0.8947 | 0.9092 | 0.9165 | −0.0146 (−0.0213, −0.0080) | −0.0219 (−0.0280, −0.0164) |

  差距从 ≈0.03–0.04 缩到 ≈0.015–0.02(约缩小一半), **仍然略低于同行**, 没有追平。
- **Agent 端到端 episode: 全部 z=0**, 原因不是工具(§3): medium 配置下策略 token 用尽 200k 仍未接 `submit`; 诊断用的 low 配置下能接 `submit` 并通过验收(val primary 0.690), 但提交后继续精调仍超 200k。

## 1. 为什么加这个工具(根因)
同行(Kermut、ProteinNPT)都用预训练蛋白语言模型表征; 我们的 `proteinfit` 只用 DMS 监督特征 + 留一位点统计。沙箱没有 torch 也没有权重, agent 没有途径拿到 PLM 信号。ESM-2 650M 在服务器上可跑, 整批 assay 的 masked marginal 只需约 2 分钟。

## 2. 工具与选型(只用 src 52 个 assay 的 dev, 没读 id/ood)
- dev 上逐个 assay 比较零样本 ESM 打分、旧集成、加 1/2/6 个 ESM 特征列的集成(`scripts/f31/dev_eval.py/.log`): 6 列 +0.0281, 2 列 +0.0261, 1 列 +0.0239; 选用 6 列(差异在噪声内, 保留最完整的)。零样本 ESM 打分单独只有 0.405(masked) / 0.396(wt marginal), 远低于监督集成 —— 增益来自"把 PLM 信号作为特征喂给监督集成"。
- **负结果**: 加入 ESM 隐层 embedding 的 PCA 主成分(4/8/16 维)没有收益(+pc8 0.6631 对 0.6633, 差 −0.0002, 95% 区间含 0; `dev_emb.log`), 所以没有做成工具, 相关代码已删除。
- agent 可见文档只写事实(函数、参数、特征含义、耗时), 没有阈值/边际/"应该用哪些特征"的配方。`describe_extra("proteinplm")` 仅在 `available()` 时展示。
- 测试: `tests/test_scilib_proteinplm.py`(可用性、输入检查、桥路由、特征装配、窗口切分、`plm=True` 与显式额外列等价); 相关测试全部通过。

## 3. Agent 端到端 episode —— 全部 z=0(如实列出, 不挑)
统一配置 `configs/probe_strong.yaml`(策略 lab-gpt-5.5, reasoning_effort=medium, 执行器 lab-gpt-5.4-mini), 与 FoR30/32/36/47/51 的 tool-ON 运行相同。

| run | split | 条件 | 结果 | 步数 | 策略逻辑 token | 备注 |
|---|---|---|---|---|---|---|
| `toolon_f31_id` e00 | id | 有 PLM 工具 | z=0, completed=False | 19 | 203,445 | 从未接通有效 `submit` |
| `toolon_f31_id_try2` e00 | id | 同上 | z=0 | 19 | (缓存重放) | **是 try1 的缓存重放(cached_llm_calls=19, 0 新 token), 不算独立样本** |
| `toolon_f31_id_try2` e01 | id | 同上 | z=0, completed=False | 19 | ≈201k | 独立样本 |
| `toolon_f31_val_b1` ×2 | val | 有 PLM 工具 + `plm` 标志 | z=0 ×2 | 20, 20 | 209,567 / 207,455 | 从未接 `submit` |
| `ctrl_f31_val_noplm` ×2 | val | **没有 PLM 工具的对照**(桥未开, `proteinplm.available()`=False; `proteinfit` 文档里仍写有 `plm` 标志, agent 试过一次并回退) | z=0 ×2 | 21, 21 | 207,157 / 200,563 | 同样从未接 `submit` |

- **诊断(不同配置, 仅 val, 不计入上表的 tool-ON 结论)**: `runs/diag_f31_val_low`, 配置 `configs/probe_strong_low.yaml`(只有策略 reasoning_effort 由 medium 改为 low, 其余同), val n=2, 有 PLM 工具。结果: 两个 episode 都**接了 `submit`**(步 11 / 步 13 首次接通), agent 自己用了 PLM 特征(`predict_plm`/"PLM augmented"), **completed=True、accepted=True、reproducible=True, val primary 0.6896 / 0.6896(对参考线 norm 1.26 / 1.24)**; 但 agent 提交后又花 6–8 步继续精调(PLM 混合权重 0.8/0.9、逐 assay 选择器、软选择), 逻辑 token 208,100 / 205,046 > 200k, **z=0**(stop=token_budget, 步 19 的累计计费)。这与 FoR32/51 的"提交后继续精调超支"同型。此诊断只是为了分清"能力"与"预算纪律", 结果并未被用来挑选哪个配置算正式结果; 其他学科的 tool-ON 数字都是 medium, 没有换配置重跑任何一个。
- **失败与 ESM 无关**: 去掉 PLM 工具的对照同样 z=0, 同样"步数耗尽 token、从未接 `submit`"。轨迹(对照 e00): 步 3 就用 `proteinfit` 算出全部预测, 步 4 给 dev 打分, 之后 16 步都在做 PLM/种子/融合/逐 assay 选择器等候选的对比与再打分, 最后一步还在构造"按 dev 选最优"的选择器, `submit` 节点始终没加。
- 在 source/val/eval 判定下, "从未算出有效 y"= completed=False, 所以这类 episode 是**可见的失败**(不同于 FoR32/51 的"提交后超支", 后者 source 模式看不到)。
- **同一现象在其他 tool-ON 学科都出现**: FoR30 210,006 (z=0)、FoR32 204,297 (z=0)、FoR36 209,127 (z=0)、FoR51 202,437 (z=0), FoR47 累计 211,000 但 z=1(判定只计"最后一个 y 被算出的那一步"的累计 token, 之后的步不计)。所有 tool-ON 运行的 agent 都在 19–22 步用尽 200k。
- **来源更正(重要)**: 总表里 FoR31 早先的"z=1, 43k token, 7 步"轨迹来自 `configs/full_local.yaml`(自托管 Qwen 27B, 非 thinking, 提交很快), 不是 gpt-5.5 medium。`runs/final_a0_*` 里 FoR31 的对应 episode 是那些缓存轨迹的重放。两种策略模型的 episode 行为不可直接比较。
- 我没有改预算、验收线、R_src、门槛, 没有放宽任何东西, 也没有因为失败而重跑挑结果。

## 4. 池评测细节
- `scripts/f31/pool_eval.py`: 用同一套 `fit_predict_assays`(同种子、同 6 个模型、`pool=True`), 只差是否 `plm=True`; 结果 JSON `pool_id.json` / `pool_ood.json`, 日志 `pool_id.log` / `pool_ood.log`。同行数字取官方 CSV `DMS_substitutions_Spearman_DMS_level_fold_random_5.csv` 的对应 assay(`kermut`、`proteinnpt` 列)。
- 过程披露: **工具配置(6 列)在看 id/ood 之前已由 src dev 固定**; id/ood 每个各只评一次, 没有据此调整。先有 episode 再做池评测。

## 5. 披露
- **预训练数据重叠**: ESM-2 650M 在 UniRef50 上训练(掩码语言模型, 没有任何适应度标签)。基准蛋白的同源序列可能出现在 UniRef50 中, 我们无法排除这种重叠。ProteinNPT/Kermut 也使用 ESM 类表征, 这一点对同行同样成立。
- 评测协议差异: 同行是 random-fold、80% 标签训练; 我们每个 assay 训练变体 ≤1024、dev ≤32, 查询 ≤128。因此"新 − 同行"的负值含协议成分, 不应解读为方法本身落后或领先。
- ood 池是 Tsuboyama 稳定性数据集(蛋白不相交), 但 ESM-2 对稳定性类数据的零样本能力本就较强。
- 仅 tool-ON; 没有新做"关工具"对照(表中"旧 `proteinfit`"是历史工具版本, 不是关工具基线)。`ctrl_f31_val_noplm` 是"没有 PLM 工具"的对照, 用来判定失败原因, 不是关工具基线。

## 6. 剩余
- 与同行的 ≈0.015–0.02 差距 → 需要更强的 PLM(更大的 ESM、ProSST、结构条件模型)或同行那样的 80% 训练标签; 本机可见数据不变, 留待决定是否再引入。
- episode 层面的"见好就收 / 及时接 `submit`" → 留给 Skill/Operator 进化(无手写配方); 已确认各学科 tool-ON 普遍出现。
