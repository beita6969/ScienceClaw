# f39 — FoR39 (Eedi NeurIPS'20 Task 4, 10-mask accuracy ↑): 能否用"同行的工具"再提高? 结论: 现有 IRT 工具已在同行区间内, 没有改工具

标注: [实测] = 服务器 GPU 2 / 本机实际跑出(脚本 `scripts/f39/`), [源] = 文献, [估计] = 判断。
口径: 只看 tool-ON; 只用**可见训练学生**(4854 人)做评测, 没有读 id/ood 池。

## 0. 结论
- 缺口来源(此前 §11.2): 我们池内 0.694/0.692 vs Task 4 冠军 0.7474(私有集); BOBCAT 的 IRT/BiNN 系 0.677–0.700。**在 IRT 区间内**; 与冠军的 ~5 点里 ≈2–3 点是查询规则(官方 starter 允许查询目标格, 本仓库禁止), 其余是冠军的元学习集成。
- 本轮做的事: 在 4054 个训练学生上拟合、800 个训练学生做伪验证(每人 20% 作答格为目标、其余可查询, 与适配器的 dev 协议同形), 比较几种可合规加入工具库的改进。**没有一个给出可信的提升**, 所以 `scilib.adaptive` 不改。
- 已有工具的一个事实(文档里已经写明, 本轮只是量化): 多轮选题(`query_answers` 链式调用)比单轮 batch 多约 +0.4~+0.5 点。

## 1. 伪验证结果 [实测] (800 人, 约 4.4 万目标格, 单个划分, 标准误 ≈ 0.25 点)
| 方法 | 准确率 |
|---|---|
| 训练集多数正确率参考 | 0.6314 |
| IRT 无任何查询 | 0.6313 |
| IRT, 随机 10 题 | 0.6828 |
| IRT, `batch` 单轮 10 题(工具默认) | 0.6913 |
| IRT, `bald` 单轮 10 题 | 0.6886 |
| IRT, `batch` 5+5 两轮 | 0.6952 |
| IRT, `batch` 2×5 五轮 | **0.6967** |
| IRT, `batch` / `bald` 10×1 逐题 | 0.6953 / 0.6953 |
| 神经网络预测器(输入: 已作答题集合 + 已揭示答案 + 学生元数据; 随机揭示训练, 60 轮): 随机 10 题 / IRT-batch 10 题 | 0.681–0.682 / 0.683–0.685 |
- "已作答题集合"(哪些题被这个学生答过)+ 元数据没有带来可测的增益: NN 与 IRT 随机揭示持平, 在 IRT-batch 揭示下反而低 0.7 点(NN 只用随机揭示训练, 分布不匹配; 我没有继续做基于策略的训练, 见 §3)。
- 同一份 IRT 工具, 官方 starter 规则下整池是 0.715/0.720(旧结果), 与严格规则下 0.694/0.692 的差就是冠军差距里"规则"的那部分。

## 2. 为什么不改工具
- 增益在噪声边缘(多轮 +0.4~0.5 点已经在工具里, NN 无增益)。
- FoR39 的 episode 通过率本身受"验收边际 0.02 + 16 项切片噪声"限制(上限约 72%), 改 0.3 点对通过率几乎无影响。
- 之前的 F5 审计结论不变: 分数基本等于工具库默认输出, 不是 agent 的能力证据。

## 3. 没做的、以及原因
- BOBCAT(Ghosh & Lan, IJCAI 2021; 冠军团队的方法)那种"双层优化训练的选题策略 + 元学习预测器": 需要 GPU 训练与桥接, 文献里相对强 IRT 选题的增益约 1–2 点 [估计]; 投入大、收益不确定、且和冠军同一团队的私有集协议不可比, 暂列为候选。
- 多划分/多种子的伪验证: 本轮只有 1 个划分(标准误 0.25 点), 结论只用来"不改工具", 不用于报数。

## 4. 披露
- 伪验证只用可见训练学生, 没有读 id/ood 池; 脚本 `scripts/f39/{export_train,exp_nn,exp_policy}.py`; 无新的 episode 运行。
