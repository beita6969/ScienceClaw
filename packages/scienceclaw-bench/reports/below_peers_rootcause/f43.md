## 0. 结论
- **没有改任何 agent 可见内容**(没有新增 scilib 工具、没有改 `docs/tasks/FoR43.md`、没有改 objective)。原因: 现成权重 OCRonos 单独用确实有效, 但**不如我们已有的 LLM 流水线**, 与它组合也没有稳定增益, 且在干净页面上会变差。
- 用户在中途明确要求"不要自己训练, 用别人训练好的权重或代码"。我此前启动过 ByT5-base 的 OCR 校正微调(两组超参并行, 计划各 1600 步, 日志最后一次读数在第 150 步附近, 随后被我主动停掉, **没有产出任何评测结果**), 随后改用公开权重。这段探索没有进入任何数字。
- 同行对照(`reports/overnight_20260930.md` §11)的判定不变: **CONSISTENT(中游)**。我们的 LLM 流水线在 4 个已存 episode 上相对复制 OCR 的降幅是 −40.5%(id)/ −45.6%(ood); BLOCR(零样本)官方降幅 −53%, L3i(微调 Qwen3-14B)−22%, BnF-Mistral(持续预训练 + LoRA 微调的 24B)−78%。两个池与官方测试集不同, 绝对数不可直接比。
- 与 BnF-Mistral 的差距来自持续预训练与大规模微调; 我没有找到其公开权重 [估计: 只做了网页检索, 未穷尽], 在"不自己训练"的约束下无法复现这一档。

## 2. 选型(只用 src/val, 353 个单元) [实测]
复制 OCR(参照): src 0.0230, val 0.0199(加权 cMER-micro, 越低越好)。`scripts/f43/eval_sv.log`:

| 分段大小(字符) | 原始输出 src / val | 改动过滤 k=2 | k=3 | k=4 | k=6 |
|---|---|---|---|---|---|
| 300 | 0.1196 / 0.1001 | 0.0162 / 0.0133 | 0.0163 / 0.0133 | 0.0173 / 0.0137 | 0.0201 / 0.0157 |
| 700 | 0.0484 / 0.0543 | 0.0158 / 0.0132 | **0.0157 / 0.0131** | 0.0165 / 0.0134 | 0.0187 / 0.0146 |
| 1200 | 0.0588 / 0.0452 | 0.0159 / 0.0130 | 0.0159 / 0.0126 | 0.0168 / 0.0130 | 0.0198 / 0.0140 |

- 过滤 = `scilib.ocrfix.filter_hunks`: 词级比较, 一处改动只在规范化后不超过 k 个字符编辑时才采纳。
- **原始输出比不修正还差**(0.048–0.120 vs 0.023): OCRonos 会重写文本。有用的部分只有"小改动"。
- 另外试过: 编辑率上限 0.15(无益)、连字符合并 `join_line_hyphens`(无差别)、三个分段版本的改动投票(`scripts/f43/vote_sv.log`, k=3 时需 2/3 一致 src 0.0156 / val 0.0128, 与单版本无异)。
- 三种分段大小在 k=2–4 之间互相差在噪声内; 选了 700 字符、k=3(最先跑的一个, 也是 src+val 合计最低之一)。选择度: 3 个分段 × 7 个过滤设置, 共约 21 个候选, 差别很小, 所以 src/val 上的 −32% / −34% 略偏乐观。

## 3. 预先写定的流水线(看 id/ood 之前固定)
- **P1** = OCRonos(贪心, 约 700 字符一段, 按空格/换行切) + `filter_hunks(max_hunk_edits=3)`(逐段), 在整个 id / ood 池上评。
- **P2** = 已存的 LLM 流水线输出(早先 agent episode 的 `y.pkl`, 即 `ocrfix` plan→llm→merge 的结果)与 OCRonos 的改动(≤2 个规范化字符编辑, 且与 LLM 已有改动不重叠)取并集。P2 的参数 k=2 在 64 个 src/val 单元上选自 {2,3,4}(0.01145 / 0.0118 / 0.01232, 对比 LLM 单独 0.0118, 差别很小)。P2 只能在有已存 LLM 输出的 4 个 episode(每池 2 个, 共 64 个单元)上评。

## 5. 解读
- OCRonos 加过滤后**显著**优于复制 OCR(两个池的区间都不含 0), 但**不如已有的 LLM 流水线**(id 上 −33.8% vs −40.5%, ood 上 −25.9% vs −45.6%, 同一批 64 个单元)。
- 并集 P2 在 id 上点估计更好 10%、ood 上更差 4.5%, 两个区间都含 0。没有证据表明在 LLM 流水线之上叠加 OCRonos 有用。
- OCRonos 在干净页面(dta19-l0, 复制 OCR 已是 0.0031)上把错误翻了近 4 倍。这与同行总结一致(低噪声页面上的过度改写)。`ocrfix` 已有的"训练 OCR 的 cMER 低于 0.008 的 test set 不送 LLM"规则正好避免这个问题; OCRonos 没有这个保护。
- 这是 FoR43 的一个"现成权重不构成提升"的负面结果, 不是该学科的新缺口: 学科在同行对照里已是 CONSISTENT; 与 BnF-Mistral 的差距属于持续预训练 + 微调, 超出"只用别人训练好的权重"的范围。

## 6. 披露与局限
- 预训练数据重叠: OCRonos 在 PleIAs 开放预训练语料(Common Corpus 的文化遗产部分、Finance Commons)上训练, 模型卡没有给出具体数据列表。HIPE-OCRepair / ICDAR 2017 / Impresso / DTA / Overproof 的文本是否出现在其中**不知道, 也不能排除**。
- 统计: 池级结果以单元为单位 bootstrap; 4 个 episode 的配对比较只有 64 个单元, 区间很宽, 只能说"没有可检出的差别"。P2 用的是早先 agent 运行存下的 LLM 输出(不同批的网关调用), 没有重新跑。
- 选择度: src/val 上约 21 个候选里选 1(P1), P2 的 k 在 3 个里选 1; id/ood 没有参与任何选择。
- 网关(lab-gpt-5.5 / lab-gpt-5.4-mini)仍是 HTTP 502, 因此没有做 agent 端到端的新 episode; 本报告全是离线、固定流水线的结果。
- 没有新增 token 预算相关结论: 所有 tool-ON episode 仍因超过 200k 逻辑 token 而 z=0, 与本次实验无关。
- 失败/偏路记录: ByT5 微调(已停, 无结果); 第一次 Range 下载错误(见 §1); 一个脚本因为被 import 而重复执行了探索代码(`combo_sv.py`, 已加 `__main__` 保护, 结果不变)。
