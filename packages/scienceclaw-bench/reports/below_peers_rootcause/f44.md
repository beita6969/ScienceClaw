# f44 — FoR44 (ACIC 2016, SATT 的 RMSE/sd(y) ↓): 工具增强(tool-ON)后的结果

标注: [实测] = 本机实际跑出(脚本与结果在 `scripts/f44/`), [估计] = 判断, 未测。
口径: 只评"开工具"版本。id 池每个方法只评一次, 没有据此再调参(选型只用 dev+src 共 64 个模拟数据集)。ood 池为空。

## 0. 结论
- 工具: `scilib.causal` 新增 `bart_effect`(联合 BART, 以 z 为一列协变量, 对处理组反事实预测)与 `bcf_effect`(Bayesian Causal Forest, 带估计倾向得分), 都用 `stochtree` 0.4.5(BART/BCF 作者团队的库), 在 `stochtree` 可导入时分别注册为方法名 `bart` / `bcf`, 可直接用于 `estimate_effects(methods=[...])`。每个数据集只用它自己的观测数据拟合, 没有预训练权重, 没有外部数据。
- **关键发现(收敛)**: BART/BCF 必须跑到收敛的 MCMC(`num_gfr=0`, burn-in 300, 1000 次采样)。用 10–20 次 GFR 暖启动或只采 100 次时严重未收敛, 同一批数据上差几倍(前 12 个数据集: 0.0700 对 0.0079)。这是我第一次试 BART 时得到"BART 比 LightGBM 还差"的原因, 不是方法本身的问题 [实测, `scripts/f44/conv.log`]。
- **工具本身的增益**(RMSE/sd(y), 同一批数据、只换估计器)[实测]:

| 池 | n 个数据集 | 默认(impute_lgbm + xlearner_lgbm 均值) | 联合 BART | **BCF** | BCF − 默认 (95% bootstrap) |
|---|---|---|---|---|---|
| dev+src(选型) | 64 | 0.0198 | 0.0161 | **0.0143** | −0.0055 (−0.0088, −0.0025) |
| id(一次) | 64 | 0.0227 | 0.0207 | **0.0193** | −0.0035 (−0.0090, +0.0027) |

  id 上的点估计同方向(BCF 比默认低 15%, 61% 的数据集更好), 但**95% 区间含 0**: 误差由少数数据集主导(默认与 BCF 都有约 46–47% 的平方误差来自 3 个数据集)。去掉各自最差的 3 个后: 默认 0.0171, BCF 0.0143。BCF 与 X-learner 的均值在 id 上 0.0192, 配对差 −0.0035 (−0.0065, −0.0001), 区间不含 0 但边缘; BCF + 联合 BART + X-learner 三者均值 0.0191。这些组合是事后在 id 上看到的, 不据此改默认。
- 对同行(BART 族 ≈0.010–0.020, 线性模型 0.12–0.14; Dorie 2019 / Hahn 2020, 见 `reports/overnight_20260930.md` §11)[实测对比]: 工具前我们在各池上的数字是 0.0209–0.0313(id 默认 0.0227), 高于 BART 族区间的上沿 0.020; BCF 在 id 上 0.0193, 落进该区间的上沿内, 但**离 BART 族的下沿(0.010)仍远**; 协议并不严格相同(同行数字是各自论文的 ACIC 2016 子集/重复, 我们是 dev+src 选型、id 一次)。不能据此声称追平或超过同行, 只能说"不再明显低于同行区间"。
- **Agent 端到端 episode: 本报告没有跑**。所有其他学科的 tool-ON episode 都在 19–22 步用尽 200k token(z=0), FoR44 预期同型; 且 16 个模拟数据集的 BCF 约 8 分钟, 超过 600 s 节点上限, agent 需要自己拆分节点。是否补跑见 §3。

## 1. 为什么加这个工具(根因)
同行(BART 族)都用 BART/BCF 这类贝叶斯树集成, 在 ACIC 2016 上 RMSE/sd(y) 约 0.010–0.020; 我们的 `scilib.causal` 只有 ridge/HistGB/LightGBM/随机森林学习器与 X-learner/AIPW/IPW, 默认 0.0198(dev+src)/0.0227(id)。沙箱里没有 BART/BCF 的实现, agent 没有途径自己写出一个收敛的 MCMC 采样器(尝试自写估计器是 FoR44 episode 里常见的耗 token 方式)。`stochtree` 是纯 CPU、可 pip 安装的 BART/BCF 作者团队的库, 放进 `.venv` 后沙箱里 `import` 可用。

## 2. 工具与选型(只用 dev+src 64 个数据集, 没读 id)
候选与结果(`scripts/f44/devsrc_est_all.json`, `devsrc_eval_long.log`, `devsrc_eval_short.log`; RMSE/sd(y), 64 个数据集)[实测]:

| 方法 | RMSE/sd(y) | 相对默认 (95%) |
|---|---|---|
| **bcf**(burn 300 / draws 1000) | **0.0143** | −0.0055 (−0.0088, −0.0025) |
| joint_bart + bcf | 0.0148 | −0.0050 (−0.0085, −0.0018) |
| joint_bart + bcf + xlearner_lgbm | 0.0154 | −0.0044 (−0.0075, −0.0017) |
| bcf + bcf_short | 0.0155 | −0.0043 (−0.0076, −0.0013) |
| bcf + xlearner_lgbm | 0.0156 | −0.0041 (−0.0068, −0.0019) |
| joint_bart | 0.0161 | −0.0037 (−0.0080, +0.0005) |
| bcf_short(burn 150 / draws 500) | 0.0169 | −0.0029 (−0.0064, +0.0004) |
| xlearner_lgbm | 0.0182 | −0.0015 (−0.0037, +0.0001) |
| 默认(impute_lgbm + xlearner_lgbm) | 0.0198 | 0 |
| impute_lgbm | 0.0264 | +0.0066 |
| regression_adjustment(OLS) | 0.1165 | — |

- **选定**: BCF 完整链为首选, 联合 BART 为次选; 两个都以单线程、`num_gfr=0`、burn-in 300、1000 次采样作为 `bart_effect`/`bcf_effect` 的默认值。`estimate_effects` 的默认方法**没有改**(`impute_lgbm` + `xlearner_lgbm`): BCF 约 30 s/数据集, 默认方法 0.3–1.5 s, 由 agent 自己按预算取舍, 文档只写耗时。
- 短链 BCF(burn 150 / draws 500, 约 16 s/数据集, 一半耗时)显著不如完整链(0.0169 对 0.0143, 差 +0.0025)。
- **负结果**: ① 分臂 BART(只用对照组拟合 μ0 再插补)在这个口径下 0.0499(`scripts/f44/devsrc_eval_unconverged.log`, 未收敛设置); ② 短链联合 BART(100 次采样, GFR 暖启动)0.0639, 差几倍(同一日志)。这两项都被确认是**未收敛**造成的(§0 关键发现, `conv.log`: `gfr0_burn300_mcmc1000` 0.0079 对 `gfr20_mcmc500` 0.0212 对 `gfr0_burn100_mcmc300` 0.0185), 不是方法本身; 用收敛设置重跑的联合 BART 为 0.0161。
- 线程: 多线程基本无加速(BCF 单线程 30.4 s/数据集, 2 线程 34.3 s; `bcf_speed.log`), 所以固定单线程(共享机器上的沙箱友好)。
- agent 可见文档只写事实(函数、参数、耗时, 收敛设置的取值), 没有阈值/边际/"应该用哪个"的配方; `tests/test_scilib_causal.py::test_interface_text_is_factual` 通过。
- 测试: `test_bart_method_is_registered_and_recovers_the_effect`、`test_bart_is_deterministic_for_a_seed_and_differs_across_seeds`、`test_bart_inside_estimate_effects`、`test_bcf_recovers_att_and_ate_and_is_deterministic`(以 `stochtree` 是否可导入做 `skipif`); 21 个测试全部通过。

## 3. Agent 端到端 episode
本报告没有跑 FoR44 的 tool-ON agent episode, 原因: ① 其余 tool-ON 学科(FoR30/31/32/36/51)都在 19–22 步用尽 200k token 而 z=0, 原因与具体工具无关(提交后/提交前持续精调), 在 FoR44 补跑得到的信息有限; ② BCF 对 16 个模拟数据集需约 8 分钟, 超过 600 s 节点上限, agent 必须自己拆分节点, 需要单独设计测试。这一项没有完成, 不是失败也不是通过, 记在 §6。

## 4. 池评测细节
- `scripts/f44/export_items.py` 把一个池(dev/src/id)按数据集导出为 pickle(Y, Z, 协变量, 真实 SATT 仅用于评分, sd(y)), `scripts/f44/pool_eval.py` 对每个方法逐数据集拟合并把估计值(裁到 ±4 sd(y), 与 `estimate_effects` 的默认一致)存成 json(可断点续跑), `scripts/f44/score.py` 计算 RMSE/sd(y)、方法均值组合与配对 bootstrap(4000 次)相对默认的差。
- 过程披露: **工具配置(完整链 BCF 优先, burn 300 / draws 1000)在看 id 之前已由 dev+src 固定**; id 池每个方法各只评一次(`id_est.json`, `id_eval.log`); id 上的组合(BCF+X-learner 等)是事后看到的, 不进入默认。

## 5. 披露
- **预训练数据重叠**: 无。BART/BCF 每个数据集只用自己的观测数据拟合, 没有预训练权重, 没有外部数据。
- ood 池为空(`bench` 里 FoR44 的 ood 为 0), 没有任何 ood 结论。
- ACIC 2016 的模拟数据是公开的(Dorie et al. 2019, 同行 BART 族也在此上评测); 我们的 dev/src/id 切分按数据团队的角色划分, 与同行协议的细节不同, 不能直接判胜负。
- 估计器对每个数据集产生的估计量是 SATT(处理组 ATT), 与评分一致; `ate` 估计量也在工具中实现并有测试。
- 仅 tool-ON; "默认"是历史工具版本(impute_lgbm + xlearner_lgbm), 不是关工具基线。

## 6. 剩余
- id 上 BCF 对默认的配对区间含 0(64 个数据集, 误差由少数数据集主导); 想要更窄的区间需要更多独立数据集, 目前 dev/src/val/id 池已按数据团队划分用完, 没有另外的新池。
- episode 层面的预算纪律与 §3 的节点拆分 → 留给 Skill/Operator 进化(无手写配方)。
- 与 BART 族下沿(≈0.010)仍有差距: 可考虑 `bart_effect` 之外的倾向得分/调参, 但 id 已看过一次, 不再据此调参。
