# f48 — FoR48 (ContractNLI 证据 mAP ↑): 工具增强(tool-ON)后的结果

标注: [实测] = 本机/服务器实际跑出(脚本与结果在 `scripts/f48/`), [估计] = 判断, 未测。
口径: 只评"开工具"版本。id/ood 池每个配置各只评一次, 没有据此再调参(选型只用官方 train 划分内的合同, 没读 id/ood 评测合同)。

## 0. 结论
- 工具: 新增 `scilib.textenc`(BGE-large-en-v1.5 句向量、BGE-reranker-large 相关性、DeBERTa-v3-large NLI; 沙箱没有 torch, 走文件中转桥到 Node0015 的 GPU 2, 白名单 `textenc.embed/relevance/nli`); `scilib.contracts.ContractModel` 新增 `plm=True`(或 `PLM_GROUPS` 的子集 rerank / nli / cos / emb_lr / emb_knn), 把这些分数作为第二阶段 LightGBM 的额外特征。
- **工具本身的增益**(同一批 episode、同一份可见数据、同种子, 只差 `plm`)[实测]:

| 池 | 对数 / episode | 参照(词面重叠) | 旧 `plm=False` | **`plm=True`** | 配对差 (95% 合同簇 bootstrap) |
|---|---|---|---|---|---|
| id | 320 / 20 | 0.340 | 0.8419 | **0.8643** | +0.0224 (+0.0094, +0.0365) |
| ood(SEC 申报) | 480 / 30 | 0.335 | 0.8717 | **0.8918** | +0.0201 (+0.0070, +0.0328) |

  上表用的是由最终版 `textenc` 代码重算的分数表(v2, 主结果); 早先用旧分词路径预计算的表(v1)给出 id 0.8622 (+0.0203), ood 0.8890 (+0.0173), 同向同量级(§4)。P@R80(逐对均值, v2)id 0.757→0.792, ood 0.803→0.828; 二分类标签准确率基本不变(id 0.894→0.891, ood 0.908→0.906)。验收(参照 + 0.10)两种配置在所有 episode 都通过。逐 episode(v2): id `plm=True` 优于旧模型 14 / 20、劣于 6 / 20, ood 27 / 30 优、3 / 30 劣 —— 增益是平均意义上的, 单个 episode 可以变差(最差一例: id −0.037, ood −0.038)。
- 开发集(官方 train 划分, 40 份合同训练 / 30 份留出, 6 次重复)给出同向、同量级的增益(id +0.018, ood +0.011), 与池结果一致, 没有过拟合到池上的迹象。
- 对同行(Koreeda & Manning 2021; 见 `reports/overnight_20260930.md` §11): BERT-large 0.922、SVM 0.836、DeBERTa 0.936。我们 id 0.864 / ood 0.892, **仍低于 BERT-large / DeBERTa**, 高于 SVM。协议不同(同行用全部 423 份训练合同微调, 我们每个 episode 只有 40 份合同、不微调, 池也是重建的切分), 不能直接判胜负; 与同行的差距由 id 的约 0.08 缩到约 0.06(对 BERT-large 0.922 约 0.058) [实测对比]。
- **Agent 端到端 episode: 本报告没有跑**(见 §3)。

## 1. 为什么加这个工具(根因)
同行的做法是预训练语言模型(BERT / DeBERTa)微调后做逐句分类; 我们的 `ContractModel` 只有词袋 TF-IDF 与结构特征(沙箱里没有 torch, 也没有预训练权重), 第一阶段逻辑回归 + 第二阶段 LightGBM 在 40 份合同上达到 0.84–0.87, 不使用任何预训练语义信号。零样本对比说明预训练信号本身就强于词面重叠(官方 train 划分内的全部标注对, id 2730 对 / ood 1641 对; `scripts/f48/zeroshot.log`)[实测]:

| 打分 | id | ood |
|---|---|---|
| 词面重叠(参照) | 0.368 | 0.353 |
| reranker 相关性 | 0.452 | 0.431 |
| NLI 蕴含对数概率 | 0.421 | 0.417 |
| 句向量与假设的余弦 | 0.465 | 0.437 |
| reranker 与余弦各除以标准差后相加 | 0.486 | 0.467 |

## 2. 工具与选型(只用官方 train 划分, 没读 id/ood 评测合同)
- 预计算: 全部 607 份合同 38,265 个不同句子 × 17 个假设, 在服务器 GPU 2 上分片算好(`plm_scores.npz` v1 与 `plm_scores_v2.npz`, sha256 两端一致、npz 不入库; `scripts/f48/precompute.py`, `merge.py`)。开发与池评测用查表替代 GPU 调用, 值与 GPU 调用相同(§4 核对)。
- 开发集消融(`scripts/f48/dev_eval.py`, `dev_iid.log` / `dev_ood.log`; 40 份拟合、30 份留出, 种子 1000+t, 6 次重复, 约 300 对 / 次; 相对 `none` 的配对差, 95% 合同簇 bootstrap)[实测]:

| 配置 | id mAP | id 相对 none | ood mAP | ood 相对 none |
|---|---|---|---|---|
| none(旧模型) | 0.8586 | — | 0.8968 | — |
| rerank | 0.8625 | +0.0039 (+0.0011, +0.0068) | 0.8968 | +0.0001 (−0.0030, +0.0030) |
| nli | 0.8694 | +0.0109 (+0.0066, +0.0153) | 0.9038 | +0.0070 (+0.0030, +0.0112) |
| cos | 0.8612 | +0.0026 (−0.0013, +0.0064) | 0.8993 | +0.0025 (−0.0008, +0.0059) |
| rerank + nli + cos | 0.8718 | +0.0132 (+0.0085, +0.0181) | 0.9037 | +0.0070 (+0.0025, +0.0115) |
| **全部 5 组(含 emb_lr, emb_knn)** | **0.8769** | **+0.0184 (+0.0120, +0.0249)** | **0.9082** | **+0.0114 (+0.0061, +0.0167)** |

- **选定**: `plm=True`(全部 5 组)。依据: 两个池上都是最高点估计, 且置信区间都不含 0; NLI 是单项里最有用的, rerank 单独在 ood 上无增益, 但合起来仍有增益, 所以保留全部组而不是挑子集。配置在看 id/ood 之前固定; `emb_C`(嵌入逻辑回归的正则)没有调, 用默认 10。
- 默认值**没有改**: `ContractModel` / `fit_predict` 的 `plm` 默认 False(不带 `textenc` 时也能运行), 由 agent 决定是否打开; 文档只写耗时与含义。
- agent 可见文档只写事实(函数、参数、特征含义、耗时、训练数据来源), 没有阈值 / 边际 / "应该用哪些特征" 的配方。`describe_extra("textenc")` 仅在 `available()` 时展示。
- 速度修复(过程披露): 第一版 `textenc` 对每个(句子, 假设)对都重新分词, 通过桥接 40 份合同的 rerank 约需 5 分钟(超过沙箱 600 秒节点上限的风险)。改为每个文本只分词一次再拼接特殊 token, 通过桥接 40 份合同 fit 约 160 s、16 对预测约 120 s [实测, `scripts/f48/bridge_check.log`]。第一版预计算表(v1)是用旧实现算的; 最终版 `textenc` 代码定稿后, 用它在服务器上重新算了整张表(v2, `plm_scores_v2.npz`, sha256 fad76542…47ef69e; v1 为 796da42e…ca8d3), 池评测以 v2 为主结果、v1 为次要核对。新实现与 v1 的差异为 fp16 噪声量级(3000 句 × 17 假设: rerank 平均 |差| 0.0005, NLI 0.0025, NLI 个别样本最大 0.45 对数概率, 句向量最大 1.2e-4)。
- 测试: `tests/test_scilib_textenc.py`(可用性、输入检查、桥路由、白名单、文本事实性、特殊 token 模板) 与 `tests/test_scilib_contracts.py`(用假的 textenc 检查 `plm` 特征装配、确定性、子集、无训练对的假设); 相关测试全部通过。

## 3. Agent 端到端 episode
本报告没有跑 FoR48 的 tool-ON agent episode。原因: ① 其余 tool-ON 学科(FoR30/31/32/36/51)都在 19–22 步用尽 200k token 而 z=0, 与具体工具无关, 补跑得到的信息有限; ② 通过桥接一个 episode 的 fit + 预测约 4 分钟, 可放进单个 600 s 节点, 但需要单独设计; 这一项没有完成, 不是失败也不是通过。早先(`plm` 之前)的 FoR48 episode 结果见 `reports/overnight_20260930.md`。

- 过程披露: 配置(`plm=True`, 全部 5 组)在看 id/ood 之前已由官方 train 划分内的开发消融固定; id/ood 每个各只评一次; 没有改预算、验收线或门槛。

## 5. 披露
- **预训练数据重叠**: BGE-large-en-v1.5 是在大规模公开文本对上对比学习训练的编码器(BAAI); BGE-reranker-large 由 XLM-RoBERTa-large 初始化, 用多语种相关性数据训练(BAAI); NLI 模型是在 SNLI 与 MultiNLI 上微调的 DeBERTa-v3-large。ContractNLI 的合同文本是否出现在它们的预训练语料中**无法排除**; 三个模型都没有见过本基准的标签。同行的 BERT / DeBERTa 同样基于大规模预训练语料, 这一点对同行同样成立。
- 评测协议差异: 同行用全部 423 份训练合同微调整个模型; 我们每个 episode 只有 40 份训练合同(外加 8 份 dev 合同的无标签预测), 预训练模型不微调, 只作为冻结特征。因此"我们 − 同行"的负值含协议成分。
- id/ood 的切分是重建的(没有找回历史样本 id); ood 是文档来源代理(SEC 申报 vs 网络搜索 PDF), 不是真正的分布外。
- 池结果来自预计算表而非逐次 GPU 调用; 与真实桥接的差异见 §4(4 个 episode 均值 −0.004, 来源未确认)。
- 仅 tool-ON; 表中的"旧 `plm=False`"是历史工具版本(词袋 + LightGBM), 不是关工具基线。

## 6. 剩余
- 与同行(0.92–0.94)仍有约 0.06 的差距。可能的方向: 在 GPU 端对 cross-encoder 做轻量微调(需要把训练也放进桥接, 并有 600 s / 白名单的约束)、更强的 NLI 模型(训练数据更多的 DeBERTa-v3-large)、更多训练合同(本机可见数据不变)。
- `emb_C` 未调; `PLM_GROUPS` 的各组在 id 与 ood 上的贡献不同(rerank 在 ood 上无增益), 可在更多开发数据上细化, 但增益预计较小。
- episode 层面的预算纪律 / 节点拆分 → 留给 Skill/Operator 进化(无手写配方)。
