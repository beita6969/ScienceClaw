# f51 — FoR51 (Matbench phonons, 声子态密度最后一个峰 cm⁻¹, MAE ↓): 工具增强(tool-ON)后的结果

标注: [实测] = 本机/服务器实际跑出(脚本与结果在 `scripts/f51/`), [源:X] = 来源 X, [估计] = 判断, 未测。
口径: 只评"开工具"版本(agent 可调用同行的预训练势函数)。id 池、ood 池每个方法各只评一次, 没有据此再调。

## 0. 结论
- 工具: 新增 `scilib.matphonon_mlip.phonon_features` —— 预训练通用原子间势 **CHGNet 0.3.0 权重(chgnet 0.4.2)+ phonopy** 对每个结构做有限位移声子, 输出 21 维声谱统计量。GPU 在 Node0015, 沙箱经文件中转桥调用; 每结构结果按内容哈希缓存, 重放可复现。
- **更新(§7)**: 默认势换成 SevenNet-l3i5 后, 同一份方法 B 代码的池 MAE 为 id **24.8**(CHGNet 37.4)、ood **18.0**(22.2); 第 4 次 episode(try4)仍 z=0(agent 自己选了 CHGNet、未把 submit 接到 MLIP 结果、token 207k 超预算)。
- **三次 agent 端到端 episode 全部 z=0**(§3)。只有第 3 次走完了流程(completed / reproducible / accepted), 但超出策略 token 预算, 不算通过。
- 完整池评测(训练只用 676 个训练结构, 一次预测 dev+id+ood)。**两个方法都测了, 两个都报**, MAE (cm⁻¹) [实测]:

| 方法 | dev | id (n=99) | ood (n=179, Se/Te) |
|---|---|---|---|
| **A. 第 3 次 episode 实际提交的模型**(`model_eval_mlip`, 唯一走完流程的提交) | 54.01 | **58.67** (95% 区间 43.9–75.9) | **33.31** (30.3–36.7) |
| B. agent 在第 1 次 episode 里 dev 上选定的集成(`ph_dev_pred`, **从未提交**: 该次在加入 submit 节点前 token 用完) | 37.10 | **37.43** (30.0–46.1) | **22.16** (19.6–24.8) |
| 5-NN 参考(适配器自带) | 121.93 | 132.63 | 51.05 |
| 参考: 之前无声谱特征的固定 GBM(g5.md 的池复现, 与 A/B 不是同一方法) | 50.7 | 40.1 | 30.4 |

- **A 是符合协议的头条**(真实提交), **B 是同一 agent 在自己 dev 验证下写出的代码**, 即"流程若能走完时的能力"。在 B 与 A 的逐结构比较中 B 在 id 上 79%、ood 上 75% 的结构上误差更小(配对平均差 21.2 / 11.2 cm⁻¹)。哪个都不该单挑好看的引用。
- A 比无声谱固定 GBM 的 id(40.1) **更差**: 原因见 §3——最终提交的 `model_eval_mlip` 是 agent 另写的"eval 版本", 与它在 dev 上验证过的 `model_dev_mlip`(dev 40.71)不是同一份代码, 也从未在 dev 上打过分; 我把它套在 dev 上得 54.0, 比它自己的仅描述符基线(dev 48.14)还差。这是 agent 的流程失误(没有验证提交的那份代码), 不是工具或桥的问题。
- 对同行: Matbench 榜单 MegNet 28.76、MODNet 34.28、DimeNet++ 37.46、Finder comp-only 46.58(`reports/sota_crosscheck/g5.md`)。B 的 id 37.4 在 MODNet/DimeNet++ 档, A 的 58.7 落在 Finder 与 RF-SCM(67.6)之间。**都不能说超过 SOTA**: 协议不同(同行 5 折嵌套 CV、每折约 1012 个训练结构, 我们 676 个), id 只有 99 个结构、重尾(氢化物目标到 ~3600 cm⁻¹), 区间宽。
- ood 池绝对 MAE 小是**尺度假象**: ood 目标均值 286、MAD 110, id 目标均值 674、MAD 386。B 的 MAE/MAD: id 0.097、ood 0.201; A: id 0.152、ood 0.302。相对 MAD, ood 反而比 id 差约 2 倍(真实的外推退化)。

## 1. 为什么加这个工具(根因)
此前 FoR51 id 约为榜首 1.4 倍(§11.1)。缺的是"结构感知"信息: 纯成分/几何描述符(35 维)+ GBM 看不到键力常数。通用 MLIP 的 Hessian 直接给出声谱, 但已知**系统性偏软**(通用势的势能面软化, Deng et al. 2024), 所以特征只当回归输入: 在 dev 上声谱最高频统计量与目标的比值大致稳定在 ≈1.15–1.2, 用作特征后回归可以修正偏软。

## 2. 工具
- 模型: CHGNet(Deng et al., Nat. Mach. Intell. 2023), 训练于 Materials Project 轨迹 MPtrj(MIT 许可), 只用能量/力/应力/磁矩训练, **没有用声子频率**。
- 计算: 结构不弛豫; 超胞边长 ≥7 Å 且 ≤220 原子; 每个对称不等价原子/方向一个 0.01 Å 位移(phonopy, `primitive_matrix="auto"`); `task="ef"`; 8³ Γ 中心 q 网格; 三种展宽的 DOS 峰。
- 21 列: `f_max f_p99 f_p95 f_p90 f_mean f_median f_p25 top_mean top_median top_p10 top_min imag_frac f_min dos_top_s{0.1,0.25,0.5} dos_last_s{0.1,0.25,0.5} gamma_max n_sites`。失败的结构整行 NaN(不写缓存)。1265 个结构全部已缓存(1 个结构为 NaN 行, 落在 test 池里, 由 agent 的代码用中位数补)。
- 沙箱到 GPU: `scilib._remote.call(...)` 写请求文件 → Mac 侧 `scripts/remote/broker.py`(沙箱外, 经 VPS)→ Node0015 上的 `scripts/remote/worker.py`(白名单加了 `("matphonon_mlip","phonon_features")`)→ 回写响应文件; 相同请求返回同一份存下的回答, 保证重放可复现。
- agent 可见文档只写事实(F5): 函数签名、列含义、"通用势通常低估声子频率"、耗时、模型与训练数据来源(含 Materials Project 重叠披露), 没有阈值/边际/池信息。测试: `tests/test_scilib_matphonon.py`。

| 2 | `runs/toolon_f51_id_try2` | z=0, 未完成 | 同上; **大部分是对第 1 次的响应缓存重放, 不是独立样本** |

- 第 3 次 16 个结构的 MAE 73.7 高于池 MAE 58.7: 16 项切片重尾抽样噪声(氢化物等极端值)。
- 第 3 次轨迹里的 dev 分数: 仅描述符 48.14 → `model_dev_mlip` 40.71 → 变体 43.63 → 规则修正 38.36; 最终提交的却是另一份 `model_eval_mlip`(新特征、不同模型集合、固定权重), 它对应的 dev 版本从未存在过。
- 修复(对所有学科生效): 第 1–2 次暴露"agent 不知道每次回复多贵", 于是 solver 的步骤头里加了**事实性**字段 `last_reply_tokens`(上一次回复的逻辑 token 数)(commit 3d7ea4c; 预算本身没变)。**注意: 这改变了所有学科的提示头, 此前 FoR30/36/47 的运行用的是旧头**。第 3 次带新头, 仍超 11k, 因为它在最后用了两次约 640/670 s 的大集成节点。我不放宽预算, 也不为让 z=1 而重跑挑选。
- 我给 agent 的文档没有说"提交节点必须在 dev 上验证过"(那是配方, 违反 F5)。若要提高可靠性, 合规的方向是让 dev 与 eval 走同一条数据通路(例如任务的 `score_dev` 与最终提交共用同一批输入格式), 或降低每步 token 开销, 而不是改预算。

## 4. 池评测细节
- A: `scripts/f51/pool_eval2.py` + `model_eval_mlip.py`(取自 `runs/toolon_f51_id_try3/*/final_graph.json`, 原样运行); B: `pool_eval.py` + `agent_ph_dev_pred.py`(取自 `runs/toolon_f51_id/*/trajectory.jsonl` step 7, 与第 2 次缓存重放的 step 7 逐字相同)。两者都是只用训练池 676 个结构训练, 一次预测 dev+id+ood(110+99+179)。
- **过程披露**: 我先评了 B(此前误以为它是第 3 次的提交), 看到结果后才发现第 3 次实际提交的是 A, 于是补评 A, 并**决定两个都报, 且把真实提交的 A 作为符合协议的头条**。没有在看过 id/ood 之后再调任何方法。
- B: dev 37.10 与它在 episode 里的 dev 36.8 一致(种子固定, 并行数值差 0.3)。最大误差 254 cm⁻¹; 中位误差 id 23.1 / ood 19.1; p90 id 85.0 / ood 47.0。预测极值 3626 对应目标 3638(无越界)。
- A: 中位误差 id 34.1 / ood 31.0, id 最大误差 535 cm⁻¹(极端氢化物)。
- 5-NN 参考用适配器自己的 `_ref_predict`(标准化描述符 5 近邻); 验收线 0.8×参考: id 106.1、ood 40.8。B、A 在 id 上都低于验收线, ood 上 B 低于(22.2)、A 低于(33.3)。

## 5. 披露
- **预训练数据重叠**: CHGNet 训练见过 Materials Project 的结构(能量/力/应力, 不含声子频率); Matbench phonons 的晶体多数来自 MP。这是通用势的结构先验重叠, 不是标签泄漏, 请在论文里写明。
- 3 次 episode 全部披露; 第 2 次为第 1 次的缓存重放; 第 3 次 z=0 不因池评测而改写。
- 同行数字的训练量更大(约 1012 vs 676)。
- 按你的口径只报 tool-ON; g5.md 的无声谱 GBM 池数只作为已有的历史参照, 未新做"关工具"对照。

## 6. 剩余
- (已在 §7 部分解决)差距: B 的 id 37.4 仍比榜首 MegNet 28.8 高约 30%; A 更差。要缩小: 更强的势(MACE-MP-0 / SevenNet 等, 同一桥)、让 agent 在预算内稳定提交一个在 dev 上验证过的模型(§3 最后一条)。
- 优先级低于 FoR30/36/32; 在这三个之后再回来做 FoR51 的可靠性。

## 7. 工具 v2: 默认势函数换成 SevenNet-l3i5(CHGNet 保留为可选项)
标注同上。口径: 只评 tool-ON; dev 先定, 再各看一次 id/ood 池。

**动机**: §0 的 B(CHGNet 特征)id 37.4 仍比榜首 MegNet 28.8 高约 30%; 根因是 CHGNet 的势能面偏软, 声谱特征噪声大。`scilib.matphonon_mlip.phonon_features` 新增参数 `model`(`"sevennet"` 为默认, 或 `"chgnet"`; 旧 CHGNet 的缓存键不变)。SevenNet-l3i5 = Park et al., JCTC 2024(等变消息传递, l_max=3, 5 层, 5 Å 截断), 同样只在 MPtrj 的能量/力/应力上训练, 没有用声子频率。沙箱到 GPU 仍走同一座文件中转桥(白名单不变, worker 额外把 `sv_pkgs` 追加到 `sys.path`)。agent 可见文档只写事实(两个模型、训练数据、每结构耗时 0.25 s vs 0.9 s、"通用势偏软"), 没有写哪个更好。

**dev 选型(先于任何池)**: 固定方法 B 的代码(`agent_ph_dev_pred.py`, 原封不动, 5 折 OOF+贪心混合), 只换特征, 训练 676 → dev 110: CHGNet 37.10 → SevenNet **27.16**(脚本 `dev_eval.py`)。据此才决定换默认。

**池评测(一次预测 dev+id+ood, 方法 B 代码不变; `pool_eval_l3i5.py`; bootstrap 4000 次, `pool_ci.py`)** MAE cm⁻¹ [实测]:

| 特征 | dev (110) | id (99) | ood (179, Se/Te) |
|---|---|---|---|
| CHGNet(§0 的 B) | 37.10 [30.5, 44.6] | 37.43 [29.8, 46.2] | 22.16 [19.7, 24.8] |
| **SevenNet-l3i5** | 27.67 [19.9, 38.1] | **24.80 [19.1, 31.5]** | **17.97 [14.3, 23.7]** |
| 配对差 (CHGNet−SevenNet) | 9.43 [1.5, 17.1] | **12.62 [4.7, 21.0]** | 4.18 [−1.5, 8.7] |
| SevenNet 更好的结构占比 | 69% | 65% | 67% |

- id 的改进显著(配对区间不含 0), ood 的区间含 0, 只能说方向一致。中位误差 id 14.4 vs 23.1、ood 12.4 vs 19.1; p90 id 64 vs 85; 最大误差 id 182 vs 238(ood 最大 446 vs 135, 个别氢化物/重元素外推变差)。MAE/MAD: id 0.070、ood 0.176。
- **复现检查**: 用工具本身(`phonon_features`, 经桥、缓存由 `populate.py` 预先写满 1265 个结构)产生的特征重评: dev 27.60 / id **24.87** / ood **17.99**, 与脚本特征一致(GPU float32 与 DOS 峰翻转造成个别列差异, 最多一列 103 cm⁻¹, 不影响结论)。`pool_eval_l3i5mod.py`。
- 对同行: MegNet 28.76、MODNet 34.28、DimeNet++ 37.46(Matbench)。我们的 id 24.8(区间 19.1–31.5)数值上低于它们, **但不能说超过 SOTA**: 协议不同(同行 5 折嵌套 CV、每折约 1012 训练结构; 我们 676 训练结构, id 只有 99 个、重尾), 且方法 B 的代码是在 CHGNet 特征上 dev 选定后原样套用的(不是为 SevenNet 重新调的, 调了大概率更好也更难解释)。
- 披露: CHGNet 与 SevenNet 都见过 Materials Project 的结构(能量/力/应力); Matbench phonons 的晶体多数来自 MP, 这是结构先验重叠, 不是标签泄漏, 论文里要写明。

**Agent 端到端 try4**(`runs/toolon_f51_id_try4`, 新工具、缓存已预先写满): **z=0**(completed / reproducible / accepted 均为真, 16 体 MAE 40.49, 参考 203.4; 逻辑 token 207,070 > 200,000, 21 步, stop=token_budget, 墙钟 2333 s)。轨迹要点:
