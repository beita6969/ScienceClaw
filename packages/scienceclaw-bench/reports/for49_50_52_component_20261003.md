# FoR49/FoR50/FoR52 component check (2026-10-03)

This pass checked the three remaining low-comparability routes for a direct
implementation or scoring repair. It did not rerun formal episodes, read
hidden labels, change item allocation, or change acceptance.

## Findings

### FoR49

`SmtAdapter.z3_statuses` delegates to the shipped Z3 binary in a fresh
subprocess per query, bounds the requested timeout/memory/workers, validates
parameter names, and returns `unknown` on timeout, resource, memory, parser,
or CLI errors. `evaluate` scores the submitted labels directly and keeps the
fixed-time pure-Z3 result in `diagnostics` only. The objective now requires
`z3_check.status -> submit.y` and disallows a code-node solver reimplementation.
The checked implementation has no scorer shortcut that inflates the primary
metric. A second frozen solver binary or CVC5 is not present in the checkout or
runtime, so no safe SOTA replacement can be added here. The existing pure-Z3
route remains an engineering upper/lower diagnostic rather than an agent-SOTA
claim.

### FoR50

`ValueEvalAdapter.evaluate` and `scilib.valueeval.official_f1_report` implement
the same official metric: macro precision and macro recall over categories with
at least one gold positive, combined by harmonic mean. The direct implementation
parity test passes. `fit_predict` rejects evaluation labels/IDs, fits only on
visible training arguments, uses grouped OOF calibration, and returns binary
predictions with fixed provenance. The staged BGE-large diagnostic was lower
than the frozen TF-IDF route (0.54849/0.36655 vs 0.54895/0.43708 on the visible
full-pool check), so it is not an improvement and is not integrated. No scoring
bug or safe frozen checkpoint route was found.

### FoR52

`psych_fixed_predict` validates the visible session/item schema and predicts
with the shipped qlearn history model. `psych_adaptive_predict` selects only
among shipped qlearn/personal/wsls models by grouped OOF on visible training
sessions; it never accepts target/scorer fields. Both routes validate legal
keys, return provenance, and are wired to direct tool outputs in the objective.
The pooled reference and acceptance code are kept separate from diagnostics.
The task's accuracy cannot be relabelled as the literature's NLL, and no
frozen external checkpoint is staged. No safe bug fix or same-metric SOTA route
was identified.
