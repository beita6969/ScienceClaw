So the agent score is exactly what the toolkit yields and nothing is hidden in the eval inputs.
**Verdict: CONSISTENT.** Ours (1.24-1.51 K) lies between ClimODE 1.40 and FourCastNet 1.68 (5.625 deg), and far above operational NWP/GraphCast-class skill (values not found). The agent only picks hyper-parameters of a ridge model.

Caveats: selection on eval episodes, single shared-shock origin, naive is a weak reference here (naive percent-kind sMAPE 22.4 IID at 2021 vs about 17-19 at most earlier origins, f38_origins.py).
**To-do:** (1) `for38_worldbank.py:67` ORIGIN=2021 only: add an earlier-origin variant (e.g. 2017 with 2018-21 targets, or 2015) to separate structural skill from post-COVID rebound; (2) `:230-232` add ETS/Theta as a second reference (they need 0.93 of naive, so 0.97 x naive is easy for pooled models); (3) report that FoR38 primary = `scilib/macro.py` DEFAULT_MEMBERS output, and re-select defaults on visible backtests only; (4) `:73` margin 0.03 is fine given ratio sd 0.03-0.09, but pass rates per episode are ~90 % for the toolkit, so z is uninformative about the LLM; (5) id e00 z=0 came from the token budget, not from forecast quality (result.json stop_reason token_budget).

Ours (5 episodes, 16 students, one mask each): primary 0.6616, 0.7068, 0.7549, 0.7428, 0.7013 (mean 0.7135) vs majority reference 0.6301, 0.7313, 0.7046, 0.6673, 0.6164 (mean 0.670); 4 of 5 pass.
**Comparability: roughly, with three known offsets.** (a) Slice: 16 students = about 1.6 students per mask, score = mean over present masks of pooled per-mask accuracy; slice sd 0.035-0.042 for the reference and 0.034-0.044 for the delta (f39_noise.py, 5000 draws), and the mask-mean aggregation adds 10-25 % sd over pooled accuracy. The five agent refs average 0.670 vs pool mean about 0.645, and id-01 ref 0.731 is about +2.4 sd, so the slices are a bit easy (+0.02 in the reference), and the agent mean 0.7135 vs the toolkit full-pool 0.694-0.698 is within about +1 SE. (b) Query rule: the official starter `evaluation.py` uses can_query = (data != -1), which includes the target cells, and the model does not see the mask; about 20 % of queries then land on targets and copying the revealed value is a leak. The harness (`for39_eedi.py:289`) uses answered and not target. The same IRT toolkit reaches 0.715/0.720 with the starter rule vs 0.694/0.692 strict (f39_starter.py), so published numbers are inflated by about 2-3 points relative to the strict harness. (c) Published winner = private set, full 10 masks, meta-learned ensemble; BOBCAT uses its own CV split.
**Parity: exact for the formula.** `pooled_metric` (:221) / `_score` (:307-312) = pooled correct/total over target cells per mask, then mean over masks; a re-computation from the raw CSVs gives the harness reference to 6 decimals, perfect predictions give 1.0 and the inverted ones 0.0 (f39_parity.py). Differences are only structural: one mask per student (`mask = rank % 10`) and a mean over the present masks rather than all ten; the majority reference is training majority correctness per question, ties to 0 (:162-166, :304); pass = score >= ref + 0.02 (`evaluate`, :452-470).
**Leakage / easy-path audit.** None found. Student sets are disjoint between train and test, there are no duplicate answer rows across them (checked on the raw CSV), majority is taken over train minus dev, targets are never returned by `query_answers`, and the 10-answer budget is enforced by HMAC receipts unioned over the whole solve (`check_query_budget` :567-647, fails closed). The tool set discloses the target mask to the agent, which is more information than the official model gets but is harmless (it is only where to predict). Easy path: the agent's output equals the `scilib.adaptive` default (90.7-95.7 % cell agreement with the toolkit run on the same inputs, f39_extra.py); the agent only wires nodes (`select_queries(answers, can_query, [], 5)` twice, then `predict`). Budget-check messages in the trajectories ("solve ledger cannot be located") are a false alarm in the replay context, the agent revealed 5+5 distinct answers per student. The toolkit ignores `revealed_values` beyond IRT, `student_meta` and the answered pattern (kNN on the pattern adds only 0.005-0.007). Trivial outputs: prior-only IRT has pass rate 0-8 %, random-10 + IRT 65-73 %, toolkit 72-87 %, so the +0.02 rule needs the queries but any IRT + query pipeline passes about 70 % of slices.
**Verdict: CONSISTENT with IRT-class methods; BELOW the published winner (NOT-COMPARABLE in absolute terms).** Ours 0.66-0.75 (full-pool toolkit 0.69) sits inside the BOBCAT IRT/BiNN band 0.68-0.70 and is not suspiciously high; the gap to 0.7474 is about 5 points strict, about 2.7 after the starter-rule offset, plausible for a meta-learned ensemble with option-level values, metadata and multi-model averaging, none of which the toolkit uses. Caveat: 5 slices, each sd 0.04, so a single-episode pass says little.
**To-do:** (1) `for39_eedi.py:289` document the strict-vs-starter query rule, or add a starter-rule variant (+2-3 points) so quoting the challenge number is honest; (2) `:307-312` report pooled accuracy over all target cells next to the mask-mean (noise +10-25 %); (3) `:162-166` / `:304` majority is a weak reference (0.64 vs 0.69 for IRT random-10); add IRT prior-only or random-10 + IRT as a second reference so z separates query strategy from modelling; (4) `:495-501` the ood pool is a proxy_within_dataset (private-LB students have fewer answers per student), do not present it as the challenge private set; (5) `:238` consider more than one mask per student in the aggregate report; (6) runs/final_a0_v_val has one FoR39 episode only (no val-01 y.pkl), so val has n=1; (7) `scilib/adaptive.py` ignores `revealed_values` / `student_meta`, so it is a lower bound on what an agent could reach.
