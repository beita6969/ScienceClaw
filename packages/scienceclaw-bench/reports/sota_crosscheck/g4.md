## FoR45: AmericasNLP 2026 cultural image captioning (chrF++), `for45_americasnlp.py`

Ours: chrF++ 23.81 / 23.95 (id), 25.55 / 25.02 (ood), 22.43 (val); mean 23.75. Medoid reference 19.6-24.8. 8 items per episode, 64x64 thumbnails, DEV partition (test captions are not public).

Source: Findings of the AmericasNLP 2026 shared task on cultural image captioning, https://aclanthology.org/2026.americasnlp-6.27/ (PDF: https://aclanthology.org/2026.americasnlp-6.27.pdf). 8 teams, 27 systems. TEST set (101-267 images per language). Best chrF++ per team:

| Mila / InclusionVLM / usp / 6fanle (best per language) | 11.73 | 19.77 | 16.97 | 20.66 | 19.16 |

Best per language: Bribri 19.37, Guarani 24.67, Maya 23.41, Nahuatl 25.42, Wixarika 19.84. Human ratings 2.9-3.8 of 5 (task called largely unsolved). Organizer baseline on DEV (official README): Wixarika 17.77, Bribri 7.57, Guarani 20.82, Nahuatl 11.53.

### Comparability
- Ours is on DEV captions and published numbers are on TEST: only roughly comparable. The metric is the same family, but the aggregation is not stated in the Findings paper (sentence mean vs corpus). On a synthetic sample corpus chrF++ was 28.83 vs sentence-mean 26.52, so the choice matters by about 2 points.
- Noise: per-item SD 4.5 (Bribri 3.2, Guarani 3.5, Maya 7.6, Nahuatl 4.7, Wixarika 3.6), so SE about 1.6 at 8 items, 1.1 at 16. Observed spread over episodes (22.4-25.6) is inside 2 SE.

### Parity
Exact. `chrf_pp` (`for45_americasnlp.py:76-90`) is sacrebleu `CHRF(word_order=2)`. Against the official scorer (`for45-americasnlp-2026/official_scorer/eval.py`) the max abs diff over 300 random pairs was 0. Predictions are `.strip()`ed (`:481`), chrF ignores whitespace anyway.

### Leakage / easy-path audit
- Agent output is a per-language CONSTANT string (2-3 unique captions per 8 items). It comes from `scilib.captions.consensus_caption`, a greedy chrF++-maximising word string, 18-35 words, ungrammatical, image-blind.
- Leave-one-out on all 250 dev captions (train on the other 49, image-blind), chrF++:

| | Bribri | Guarani | Maya | Nahuatl | Wixarika | mean |
|---|---|---|---|---|---|---|
| medoid | 19.51 | 21.43 | 20.28 | 22.32 | 23.52 | 21.41 |
| consensus string | 23.11 | 24.69 | 24.76 | 24.72 | 26.09 | 24.68 |
| random caption | 15.90 | 17.72 | 13.51 | 16.70 | 18.79 | 16.52 |

- The image-blind string beats or matches the best published team on 4 of 5 languages (Bribri +3.7, Guarani +0.0, Maya +1.4, Wixarika +6.3; test-set caveat) and is 0.7 below on Nahuatl. chrF++ (beta=2, recall-heavy) rewards word-salad; our 23.75 is at the consensus-string level (24.7), i.e. no image grounding is being measured.

### Verdict
SUSPICIOUSLY-HIGH / NOT-COMPARABLE as a captioning claim. Metric implementation is right; the reference (medoid, 21.4 LOO) already sits at leaderboard level, so "beats ref by 1.0" says little.
### To-do
- Add a degeneracy check on the deliverable (identical or near-identical strings across items, mean unique-caption ratio, ungrammatical text) near `for45_americasnlp.py:465-490`.
- Use a stronger, image-conditioned reference (NAIST-style CLIP kNN over dev captions) and the consensus string as an explicit "gaming" baseline; report both next to the medoid.
- Score with a second metric that is not recall-gameable (human rating or a CIDEr-like one) and state sentence-mean vs corpus chrF++.

## FoR46: HumanEval to MBPP code generation (pass@1), `for46_code.py`

Ours: id pass@1 1.0 and 1.0 (n=16 each); ood 0.9375 and 0.875 (MBPP-sanitized); val 0.8125; reference 0.0. Pooled HumanEval 45/48 = 93.75%, MBPP 29/32 = 90.6%.

| Model | HumanEval | HumanEval+ | MBPP | MBPP+ |
|---|---|---|---|---|

| GPT-4o (Aug 2024) | 92.7 | 87.2 | 87.6 | 72.2 |
| Qwen2.5-Coder-32B-Instruct | 92.1 | 87.2 | 90.5 | 77.0 |
| DeepSeek-V3 | 91.5 | 86.6 | 87.6 | 73.0 |

| Claude 3.5 Sonnet (Jun 2024) | 87.2 | 81.7 | 89.4 | 74.3 |

Community submission evalplus/evalplus#299 (2026-04-17): Qwen3.6 35B A3B Q4_K_M 93.3 / 90.2 / 90.2 / 75.4. Qwen3 tech report (https://arxiv.org/html/2505.09388v1) gives only base-model EvalPlus averages (Qwen3-32B-Base 72.05).

### Comparability
- Test source matches (official HumanEval `check`, 164 base tests; MBPP sanitized 427 with all 3 asserts). Ours is base tests only (the "+" variants lose 3-15 points), MBPP-sanitized is not the 378-problem EvalPlus set. Roughly comparable.
- Noise: SE about 7.5 points at n=16, p=0.9; about 3.5 at n=64. A perfect 16/16 has probability 0.44 at true p=0.95 and 0.19 at p=0.90; two in a row (32/32) 0.19 at p=0.95, so the id scores are plausible.

### Parity
Program = prompt + completion + `check(entry_point)` for HumanEval, completion + test_imports + 3 asserts for MBPP (docstring `for46_code.py:13, 35-38`). Same per-problem verdicts as the data team's official scorer (`estimate_pass_at_k`, n=1) per the adapter; timeout 6 s per statement vs 3 s native. No mismatch found.

### Leakage / easy-path audit
- Hidden tests and canonical solutions are never exposed. Visible tests: HumanEval docstring examples (133 of 164 problems, mean 2.23); MBPP 1 of 3 asserts. Agent has `run_visible_tests`.
- Trajectory (6 steps): `scilib.codegen.build_prompts(style="direct")`, one temperature-0 LLM node, sanitize, visible-test run, submit. All 16 passed visible tests on the first try, so it is effectively single-shot greedy (no iterative gain). `scilib/codegen.py` has no canonical/hidden lookup; failures are genuine AssertionErrors.
- Contamination of HumanEval/MBPP in a 2025-26 model's training data is possible but affects every published number too.

### Verdict
CONSISTENT with modern models (HumanEval 87-96, MBPP 87-95). The reference 0.0 is a design artifact (memorizer returns None off visible inputs), not a weak-model signal.

### To-do
- Report HumanEval+/MBPP+ (extra tests) in a side metric; base-only inflates by 3-15 points.
- Drop the "reference = 0.0" from the pass/fail story (`for46_code.py:46-49, 89`); use a plain zero-shot pass@1 as reference.
- Use n >= 64 problems per score if a number is to be quoted next to a leaderboard.

## FoR48: ContractNLI evidence identification (mAP), `for48_contractnli.py`

Ours (primary = per-pair mean AP): 0.857 / 0.867 (id), 0.901 / 0.909 (ood), 0.830 (val); reference 0.283-0.462. Auxiliary: `p_at_r80` (per-pair) 0.757-0.846; `nli_binary_accuracy` 0.938-1.0 (E vs C only).

### Published numbers
Koreeda & Manning, Findings of EMNLP 2021, https://arxiv.org/pdf/2110.01799 (https://aclanthology.org/2021.findings-emnlp.164/), Table 4, test set (123 docs):

| System | mAP | P@R80 | Acc |
|---|---|---|---|
| Random | .024 | .000 | - |
| Span TF-IDF + cosine | .381 | .057 | - |
| Span TF-IDF + SVM | .836 | .322 | - |
| SQuAD BERT-base / large | .825 / .869 | .574 / .661 | - |
| Span NLI BERT-base / large | .885 / .922 | .663 / .793 | .838 / .875 |

Table 3: DeBERTa-v2-xlarge (CUAD-fine-tuned) mAP .936, P@R80 .860, Acc .892. Table 6, binary E-vs-C accuracy: majority .814, BERT-large .899. 2024-2026 LLM evidence-mAP results: not found.

### Comparability
- mAP aggregation: reproduced the paper's TF-IDF+cosine baseline (fit on train spans) on test: per-pair mean AP 0.3925 (paper .381) while pooled P@R80 0.0568 (paper .057). So the paper's mAP = per-pair mean AP (`micro_label_macro_doc`), P@R80 = pooled (`micro_label_micro_doc`). Ours uses per-pair P@R80 (see To-do). Random baseline .024 matches the pooled value (0.0245).
- Our lexical reference (per-pair mAP 0.332) agrees with the paper's TF-IDF+cosine (.381): sane.
- Ours: 40 train docs (paper 423), 16 (contract, hypothesis) pairs per episode, OOD = SEC filings inside the same corpus (proxy). Noise: 80 pairs, per-pair AP mean 0.873, SD 0.210; SE 0.053 at 16 pairs. 66% of pairs have AP=1.

### Parity
mAP exact. Official `evaluate_all` (via dataset `load_official.py`, identical to https://github.com/stanfordnlp/contract-nli-bert `contract_nli/evaluation.py`), synthetic scores on 1188 test pairs: `micro_label_macro_doc` mAP 0.685625 = ours; P@R80 (`micro_label_macro_doc`) 0.543409 = ours; `macro_label_micro_doc` mAP 0.566695 = ours. Binary accuracy differs only by pair set (official 0.8960 incl. all pairs vs ours 0.8914; the adapter keeps only E/C pairs with non-empty evidence, `:150`).

### Same predictions, the paper's pooled definitions (from `y.pkl`, episodes rebuilt)
Pooled P@R80 per episode 0.328, 0.370, 0.309, 0.267, 0.524 (mean 0.36; per-pair values for the same episodes 0.757-0.846). Pooled mAP 0.739, 0.772, 0.743, 0.784, 0.749 (mean 0.757). Only 16 pairs pooled, so noisy. Against the paper's pooled definitions the agent is at TF-IDF+SVM level on P@R80 (.322), far below BERT (.66-.86); on per-pair mAP it lies between SVM (.836) and BERT-large (.922).

### Leakage / easy-path audit
Contracts are split by document; dev/test labels never visible. Verbatim evidence-span overlap dev+test vs train (official split, so peers get it too): IID 5.9% anywhere in train (4.3% same hypothesis), OOD (SEC) 18.6% (14.6%); 5 of 70 SEC docs have >0.9 span overlap with a train doc (near-duplicate exhibits). This explains OOD (0.90-0.91) > IID (0.86-0.87). Label baseline: per-hypothesis majority on E/C pairs is 0.89 (IID 0.895, OOD 0.885), so our micro accuracy 0.94-1.0 is only 5-10 points above trivial; the paper's accuracy is macro over labels, not comparable.

### Verdict
CONSISTENT on mAP (0.83-0.91 vs .82-.94 for supervised BERT/DeBERTa, with only 40 train docs; boilerplate makes it easy). Not consistent as a "P@R80 / accuracy" claim.

### To-do
- Add the paper-style pooled P@R80 (`micro_label_micro_doc`) next to `p_at_r80` (`for48_contractnli.py:300, 305`) and label the per-pair one as optimistic (the official code says "optimistically").
- `nli_binary_accuracy` (`:301, 306`) is micro over pairs; report macro-over-labels and the majority-baseline accuracy (0.89) beside it.
- State that OOD is a within-corpus proxy (`:62`, IID_TYPES) and that `n_train_docs=40` (`:175`) vs 423 in the paper.

## FoR49: SMT-LIB 2025 QF_NIA/QF_NIRA satisfiability (accuracy), `for49_smt.py`

Ours: accuracy 1.0 / 0.875 (id), 0.875 / 0.9375 (ood), 0.9375 (val); reference (majority train status) 0.5-0.625; `n_wrong_definite` 2 in id-01, 'unknown' 1-2 in the others. 16 items = 12 hard (screen: Z3 1 s fails) + 4 easy.

### Published numbers
SMT-COMP 2025 QF_NonLinearIntArith single query, https://smt-comp.github.io/2025/results/qf_nonlinearintarith-single-query/ (raw HTML read; generated 2025-08-11; 12,280 benchmarks, 1200 s limit, 0 errors):

| Solver | correct (sequential) | timeout | solved (SAT / UNSAT) |
|---|---|---|---|
| Z3-alpha | 9965 | 2107 | 6735 / 3359 |
| z3siri | 9693 | 2385 | 6302 / 3391 |
| Yices2 | 9071 | 3189 | 6259 / 2812 |
| cvc5 | 8509 | 3499 | 5986 / 2523 |

Z3-alpha 24 s performance 9079 (about 74%). So top solvers decide about 70-82% in 1200 s. No published sat/unsat prediction accuracy without a solver for QF_NIA found; MachSMT (TACAS21, https://cs.stanford.edu/~preiner/publications/2021/ScottNiemetzPreinerNejatiGanesh-TACAS21.pdf) reports PAR-2, not accuracy.

### Comparability
NOT comparable: SMT-COMP scores solved benchmarks at 1200 s; ours scores agreement with the `:status` label at up to 120 s with Z3 available. Slice is stratified (75% hard by Z3 1 s, families by lineage, 37.5-62.5% sat). n=16 at p about 0.92: SE 0.07.

### Parity
Oracle = official `(set-info :status)` (not a solver output); frozen screen has zero Z3-vs-official conflicts on 19,930 eligible items. Metric = accuracy with 'unknown' never correct, so parity is trivially exact. No official scorer beyond status match.

### Leakage / easy-path audit
Queries are sanitized (comments, `set-info`, output commands removed), status not visible. The agent has a `z3_check` tool (`for49_smt.py:573, 633`; up to `Z3_MAX_TIMEOUT_S=120 s`, 4096 MB, 8 workers). id-00: one z3_check node (120 s, rlimit 2e8) decided all 16, output submitted, accuracy 1.0. id-01: Z3 left 2 unknown; the agent fell back to `scilib.logic.decide` with an escalating rlimit and majority-status guesses; the 2 wrong-definite answers are inferred to be those guesses (individual labels not inspected). So score = share Z3 decides within budget + a coin flip on the rest; the LLM adds almost nothing. Acceptance is ref + 0.2 (`:83`), trivial with Z3.

### Verdict
NOT-COMPARABLE as a capability claim; numerically consistent with solver performance (top solvers decide about 70-82% of the natural distribution in 1200 s, ours allows 120 s on a slice with 25% Z3-easy items).

### To-do
- Log per episode: fraction decided by Z3, unknown fraction, guessed fraction, and wrong-definite from guessing (record `n_decided_by_z3`).
- Add fair baselines through the same harness: plain Z3 at 1 s and at 120 s, and "always sat/majority" (`:605-607`).
- Consider a no-solver track, or make 'unknown' cost less than a wrong guess (currently guessing weakly dominates), before quoting the score as reasoning ability.
- Note in the paper that `HARD_FRACTION=0.75` (`:80`) uses a 1 s Z3 screen, so "hard" means Z3-hard at 1 s only, not hard for a 120 s Z3.

## Top 3 concrete bug/risk suspects (cross-discipline)
1. FoR45: image-blind consensus string (`scilib.captions.consensus_caption` output submitted as `y`) scores 24.7 chrF++ in leave-one-out, at or above the best published team on 4 of 5 languages. Scorer is correct; the task is gameable. Fix: degeneracy check + retrieval and consensus baselines.
2. FoR48: `p_at_r80` and `nli_binary_accuracy` (`for48_contractnli.py:300-306`) are not the paper's definitions. Same predictions give pooled P@R80 0.36 vs 0.76-0.85 per-pair (paper: BERT .66-.86); majority-label baseline is already 0.89.
3. FoR49: `z3_check` gives the agent the oracle-grade solver (120 s), so accuracy 0.875-1.0 measures Z3, not the agent; wrong-definite answers are majority-fallback guesses. (FoR47 is separate: 1000 training sentences and no pretrained encoder put LAS 15-20 below modern parsers; scorer exact.)
